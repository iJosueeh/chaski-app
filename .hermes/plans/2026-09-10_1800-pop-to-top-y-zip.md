# Plan: POP_TO_TOP en logout + preparación del ZIP de entrega

**Goal:** Eliminar el warning «The action POP_TO_TOP was not handled» (causa exacta identificada: nuestro `router.dismissAll()` en el logout) y dejar el repo listo para empaquetarse como ZIP limpio de entrega.

## Current context / assumptions (evidencia del repo, hoy)

**1. De dónde sale POP_TO_TOP — la prueba directa:**
`node_modules/expo-router/build/global-state/router.js:83-88`:
```js
function dismissAll() {
    if (emitDomDismissAll()) return;
    routingQueue.add({ type: 'POP_TO_TOP' });   // ← literal: dismissAll = POP_TO_TOP
}
```
**Nuestro handler de logout** (`src/features/preferences/screens/preferences.tsx`, commit pendiente) hace:
```tsx
await signOut();
router.dismissAll();      // → encola POP_TO_TOP
router.replace('/login');
```
**La carrera:** `signOut()` dispara `setSession(null)` → el RootNavigator desmonta el Stack autenticado y monta el Stack de login (1 sola pantalla). El `POP_TO_TOP` encolado puede aterrizar **después del swap** → POP_TO_TOP sobre un stack de 1 pantalla = «not handled by any navigator» → este warning. **Es no-determinístico:** a veces gana el render (warning), a veces no (por eso mi test anterior no lo vio — grepié `GO_BACK` pero no `POP_TO_TOP`, mi error). `replace('/login')` sí funciona siempre — por eso el logout ya aterrizó bien y «ahora sí funciona».

**2. ¿Se quita `dismissAll`?** Sí, es redundante aquí: al cerrar sesión, el swap **desmonta toda la pila autenticada** (wizard/plan incluidos) — su propósito ya lo cumple el swap.

**3. Estado git actual (leído hoy):** `M src/app/(tabs)/index.tsx` (avatar→Perfil), `M src/features/preferences/screens/preferences.tsx` (Volver+Cerrar sesión), 2 planes `.hermes/plans/` sin trackear. **Nada de esto está commiteado todavía.**

**4. ¿Listo para ZIP?** Casi: faltan (a) commitear lo anterior, (b) README con instrucciones de corrida (el repo no tiene uno propio con pasos .env/expo), (c) el ZIP correcto = **solo fuente, SIN node_modules** (pesa ~800MB+ y no viaja). `git archive` lo resuelve automáticamente (respeta .gitignore).

## Architecture / approach

Fix de 1 línea: quitar `dismissAll()` del handler (el `replace('/login')` permanece — es el que da la navegación determinista que pediste). Luego: commit → README de corrida → ZIP por `git archive` (fuente limpia). DRY/YAGNI: no se toca la lógica del swap ni se agrega librería de ZIP.

## Risks / tradeoffs / open questions

- **`replace('/login')` pre-swap:** si la red responde lento, replace puede ejecutarse dentro del stack autenticado un instante antes del swap; ambos caminos terminan en login (el swap lo respeta). Riesgo residual: ninguno observado; si apareciera, la alternativa es quitar replace y confiar solo en el swap (perderíamos el aterrizaje determinista).
- **Faltantes declarados para la demo (seriedad):** tab Perfil aún con diseño legacy (solo se le añadieron los 2 botones) y sin ícono propio; seed de 20 lugares esperando service_role de Josué; GPS directo es inestable en emulador (hay fallback al mapa). Nada de esto bloquea el ZIP: son límites conocidos y explicables en la sustentación.
- **¿El ZIP debe correr en otra máquina?** Si sí, el docente necesita el `.env` real aparte (o una cuenta Supabase de prueba) — queda como pregunta abierta para decidir con el grupo.
